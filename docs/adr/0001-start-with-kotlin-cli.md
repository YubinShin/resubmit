# ADR 0001: Kotlin CLI로 시작한다

- Status: Accepted
- Date: 2026-10-07

## Context

첫 목표는 Java 제출 한 건을 컴파일·테스트하고, 실행 결과에 근거한 리뷰와 힌트를 출력한 뒤 이력을 남기는 것이다. 지원 전까지 실행 가능한 증거를 만드는 것이 웹 UI나 서버 기능보다 우선한다.

이후 Spring Boot API나 웹 UI를 붙일 가능성이 있지만, 초기부터 서버를 만들면 코드 실행과 평가 workflow를 검증하기 전에 HTTP, 배포, 인증 범위가 추가된다.

## Decision

첫 버전은 Kotlin/JVM CLI로 구현한다.

- CLI는 사용자 입력과 출력만 담당한다.
- 상태 전이는 별도의 workflow 컴포넌트가 담당한다.
- Java 프로세스 실행, 리뷰, 저장은 각각 인터페이스 뒤에 둔다.
- 핵심 로직은 CLI 프레임워크나 Spring에 의존하지 않는다.
- 단일 Gradle 프로젝트로 시작하고 필요가 확인되기 전에는 멀티 모듈로 분리하지 않는다.

## Consequences

- 문제 실행과 평가 흐름을 짧은 시간 안에 검증할 수 있다.
- API 키가 없는 평가자도 fixture mode로 흐름을 확인할 수 있다.
- 서버 기능과 다중 사용자 요구사항은 검증하지 않는다.
- 이후 API adapter를 추가할 때 CLI 입출력과 핵심 로직의 경계를 유지해야 한다.
