# CLI UX

## 문서 목적

Re:Submit CLI의 사용자 흐름, 화면에 표시할 정보, 사용자 입력이 필요한 지점과 오류 처리 원칙을 정의한다.

이 문서는 목표 UX를 설명한다. 실제 구현 여부는 README와 코드·테스트를 기준으로 확인한다.

## 목표

- 사용자가 파일과 실행 명령을 관리하기보다 문제 풀이에 집중하게 한다.
- 사용자가 각 단계에서 무엇을 해야 하는지 바로 알 수 있게 한다.
- 컴파일·테스트 결과와 LLM 해석을 구분한다.
- 중단, 외부 API 오류와 잘못된 입력이 학습 기록을 유실시키지 않게 한다.

## UX 원칙

1. CLI가 세션 폴더와 `Solution.java` 템플릿을 생성한다.
2. 한 화면에는 현재 가능한 행동을 4개 이하로 표시한다.
3. 컴파일·테스트 결과를 먼저 보여주고 LLM 리뷰는 별도로 표시한다.
4. 힌트와 개선 풀이는 사용자가 요청할 때만 공개한다.
5. 중단된 세션은 실패 처리하지 않고 저장 후 재개할 수 있게 한다.
6. 기존 파일은 사용자 확인 없이 덮어쓰지 않는다.
7. LLM 오류가 발생해도 실행 결과와 제출 이력은 보존한다.
8. 숙련도 점수보다 제출에서 확인한 관찰 근거를 먼저 보여준다.
9. fixture demo와 실제 코드·LLM 실행을 명확히 구분한다.
10. 구현되지 않은 기능은 동작하는 것처럼 표시하지 않는다.

## 핵심 사용자 흐름

```text
첫 실행
  → 문제 시작
  → 세션 폴더와 Solution.java 생성
  → 사용자 편집
  → Enter로 제출
  → 컴파일·테스트 결과
  → 선택적 힌트
  → 같은 파일 수정
  → 재제출
  → 완료 기록
```

## 세션 작업 공간

CLI가 문제를 시작할 때 세션별 작업 공간을 생성한다.

```text
.resubmit/
└── sessions/
    └── 20261007-001-target-number/
        ├── Problem.md
        └── Solution.java
```

- `.resubmit/`은 Git 추적에서 제외한다.
- `Problem.md`에는 문제 설명, 제출 규약과 공개 예제를 기록한다.
- `Solution.java`에는 정답이 아닌 클래스·메서드 골격만 생성한다.
- 같은 경로에 파일이 있으면 자동으로 덮어쓰지 않는다.

템플릿 예시:

```java
public class Solution {
    public int solution(int[] numbers, int target) {
        // TODO: 구현하세요.
        return 0;
    }
}
```

## 화면별 명세

### 첫 실행

첫 실행에서는 전체 기능을 설명하기보다 예제 문제를 바로 시작할 수 있게 한다.

```text
Re:Submit에 오신 것을 환영합니다.

테스트 결과를 바탕으로 오답 원인을 분석하고,
정답을 바로 보여주지 않는 단계별 힌트를 제공합니다.

[Enter] 예제 문제 시작
[d] 기록된 데모 보기
[q] 종료
```

- fixture demo는 API 키 없이 실행할 수 있어야 한다.
- 실제 실행과 fixture 응답을 화면에 명시한다.

### 문제 시작

```text
문제: Target Number
난이도: 기본
관찰 항목: DFS, 상태 전이

작업 파일을 만들었습니다.
  .resubmit/sessions/20261007-001-target-number/Solution.java

[Enter] 편집을 마치고 제출
[h] 일반 힌트
[q] 저장하고 종료
```

- 관찰 항목은 문제 메타데이터이며 학습자의 숙련도 판정이 아니다.
- 파일 경로는 정규화된 절대 경로도 함께 표시한다.
- CLI는 제출을 기다리는 동안 세션을 유지한다.

### 에디터 열기

에디터 선택 우선순위는 다음과 같다.

1. `RESUBMIT_EDITOR`
2. `EDITOR`
3. 파일 절대 경로와 직접 실행할 명령 안내

첫 MVP에서는 특정 IDE를 자동 탐지하지 않는다. 에디터 환경변수가 없더라도 파일 경로를 복사해 열 수 있어야 한다.

### 제출 결과

실행 사실과 해석을 섞지 않는다.

```text
Attempt 1

컴파일   PASS
테스트   3 / 5 PASS
실행시간 184 ms
리뷰     READY

실패한 테스트
- case-4: expected 5, actual 3
- case-5: expected 2, actual 0

[h] 1단계 힌트
[e] 다시 편집
[q] 저장하고 종료
```

- 정오답과 실행 상태는 `CodeRunner` 결과만 사용한다.
- LLM 리뷰가 정오답을 변경하지 않는다.
- 화면에는 요약을 표시하고 stdout, stderr와 실행 명령은 상세 기록에 남긴다.

### 힌트

힌트는 자동으로 노출하지 않는다.

```text
힌트 1/3 — 방향만 제시

각 숫자마다 선택지가 몇 개인지 생각해보세요.
현재 상태에서 다음 상태로 이동하는 두 경우를 비교해보세요.

힌트를 확인한 기록이 저장됩니다.

[e] 다시 편집
[h] 다음 힌트
```

힌트 단계:

1. 관련 개념과 확인할 지점
2. 현재 제출 코드의 구체적인 문제
3. 의사코드 또는 개선 방향

완성 풀이 확인은 힌트와 분리한다. 사용자가 풀이를 확인하면 해당 attempt 이후 이력에 `solutionViewed=true`를 기록한다.

### 재제출

이전 attempt와 달라진 실행 사실을 보여준다.

```text
Attempt 2

테스트   3/5 → 5/5
결과     FAILED → PASSED
힌트     1단계 사용
변경     source hash 변경 확인
```

한 번의 통과만으로 일반적인 실력 향상을 주장하지 않는다.

### 문제 완료

```text
문제 완료

첫 제출      3/5
최종 제출    5/5
제출 횟수    2
힌트 사용    1단계
관찰 근거    재귀 상태 전이 오류 수정

[n] 다음 문제
[r] 실행 기록 보기
[q] 종료
```

## 오류 상태

### 컴파일 실패

```text
컴파일하지 못했습니다.

Solution.java:8
';' expected

[e] 파일 수정
```

- javac 오류 위치와 메시지를 우선 표시한다.
- 컴파일하지 못한 제출에는 테스트와 코드 리뷰를 실행하지 않는다.

### 테스트 실패

- 통과한 테스트 수와 실패한 공개 테스트를 표시한다.
- 숨겨진 테스트의 입력 전체나 정답을 노출하지 않는다.
- 재제출과 힌트 중 다음 행동을 선택할 수 있게 한다.

### 시간 초과

```text
실행이 2초 제한을 초과해 종료됐습니다.
프로세스는 강제로 정리했습니다.

[h] 복잡도 관련 힌트
[e] 다시 편집
```

시간 제한과 프로세스 정리 여부를 함께 표시한다.

### LLM 오류

```text
테스트 결과는 저장됐습니다.
리뷰 API가 응답하지 않아 힌트는 생성하지 못했습니다.

[r] 리뷰 다시 요청
[e] 리뷰 없이 다시 편집
```

- LLM 실패를 제출 실패로 표시하지 않는다.
- 리뷰 재시도 여부는 사용자가 선택한다.

### 잘못된 입력

전체 화면을 다시 출력하지 않고 사용할 수 있는 입력을 짧게 안내한다.

```text
'x'는 사용할 수 없는 명령입니다. 가능한 명령: e, h, q
```

## 종료와 재개

`q`, EOF와 `Ctrl+C`를 고려한다.

```text
세션을 저장했습니다.
다시 시작하면 이어서 진행할 수 있습니다.

Session: 20261007-001
```

다음 실행에서 진행 중인 세션을 발견하면 이어서 풀기와 새 문제 시작을 선택하게 한다. 제출하지 않은 편집 상태와 실패한 attempt를 구분한다.

## 명령 체계

화면별 명령:

- `Enter`: 현재 기본 행동 실행
- `e`: 제출 파일 편집
- `h`: 현재 단계의 힌트 확인
- `r`: 실행 또는 세션 기록 확인
- `q`: 저장 후 종료

전역 명령 후보:

- `?`: 현재 가능한 명령 표시
- `status`: 현재 세션 상태 표시
- `quit`: 저장 후 종료

첫 MVP에서는 화면별 명령만 구현하고, 실제 필요가 확인되면 전역 명령을 추가한다.

## 타이머

화면에 카운트다운을 표시하는 기능은 후속 범위다. 초기 구현에서도 다음 원본 시각은 저장할 수 있게 데이터 모델을 설계한다.

- `startedAt`
- `firstSubmittedAt`
- `completedAt`

pause, resume, 힌트 확인 시간 분리와 제한 시간 표시는 실제 사용 후 추가한다.

## 접근성과 터미널 호환성

- 색상만으로 PASS와 FAIL을 구분하지 않는다.
- `NO_COLOR` 환경변수를 고려한다.
- 비대화형 실행과 출력 리다이렉션에서는 ANSI 색상을 사용하지 않는다.
- 한글 메시지와 javac 원문 오류를 구분한다.
- 공백과 한글이 포함된 파일 경로를 처리한다.
- 터미널 링크 지원 여부와 관계없이 절대 경로를 출력한다.

## 사용자 화면과 상세 기록의 분리

화면에는 다음 정보만 요약한다.

- compile/test 상태
- 통과한 테스트 수
- 소요 시간
- 리뷰 상태
- 현재 가능한 행동

상세 기록에는 다음을 남긴다.

- session/attempt ID
- 실행 명령과 exit code
- stdout, stderr와 출력 절단 여부
- 테스트별 결과와 duration
- 제출 코드 hash
- hint level
- model/prompt version
- API·schema 오류

개발과 장애 확인을 위한 `--verbose` 옵션은 후속 범위로 둔다.

## 자동 진행과 사용자 확인

자동 처리:

- 세션 폴더와 템플릿 생성
- session/attempt ID 생성
- 컴파일과 테스트
- 결과 저장과 요약
- 다음 힌트 단계 계산

사용자 확인 필요:

- 기존 파일 덮어쓰기
- 힌트와 개선 풀이 확인
- 새 문제 이동
- LLM 리뷰 재시도

## MVP 범위

우선 구현:

- 세션 폴더 생성
- `Problem.md`와 `Solution.java` 생성
- 편집 후 Enter로 제출
- 컴파일·테스트 결과 요약
- 저장 후 종료

후속 구현:

- 에디터 실행
- 다단계 힌트
- 세션 재개
- 타이머 UI
- 문제 선택
- 학습 프로필과 추천
- 전역 명령과 `--verbose`
